Правила для сценаріїв:
Один або кілька Scenario на один REQ. Для REQ з суфіксами (a/b/c) — щонайменше один Scenario на кожен суфікс. Для REQ без суфікса - щонайменше один Scenario, а для вимог з декількома варіантами результату (наприклад, REQ-01, REQ-11) - по одному на варіант.
Заголовок кожного Scenario починається з ID у квадратних дужках, наприклад: Scenario: [REQ-07a] Оцінка вище 0.8 переводить коментар в «обмежений».
Ключові слова Gherkin англійською: Feature, Scenario, Given, When, Then, And, But. Текст кроків українською.
Given/When/Then описують видимий результат, як у розділі «Критерій приймання» файлу ears.md. Не додавати HTTP-кодів, таймаутів у мілісекундах, логів, NULL, підрахунку записів у БД, якщо їх немає в ears.md.
Для REQ-07b використовувати відсутність відповіді 2 с як умову; для REQ-07a - оцінку 0.81; для REQ-07c - оцінку 0.8. Не вигадувати інших порогів.
Не додавати вимог і ID, яких немає в ears.md. Не змінювати формулювання EARS.
Наприкінці файлу розділ «## Непокриті вимоги»: якщо якийсь ID з ears.md не має жодного Scenario, перелічити його з поясненням. Якщо всі покриті, написати це явно.
