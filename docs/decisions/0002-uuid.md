# 0002. UUID як тип первинних і зовнішніх ключів

* Status: accepted
* Deciders: автор проєкту (курсова робота)
* Date: 2026-10-06

## Контекст і проблема

Які ідентифікатори обрати для первинних ключів усіх сутностей і зовнішніх ключів зв'язків? Числові (autoincrement) швидші і дешевші для диска та ОЗП, бо бази даних оптимізовані під них; UUID генерується випадково і краще захищає користувачів.

## Рушії рішення

* Захист від вгадування ідентифікаторів.
* Приховування метрик проєкту (наприклад, скільки користувачів зареєстровано).
* Унікальність у межах системи без лічильників (сучасні стандарти UUID v7 частково гарантують відсутність колізій).

## Розглянуті варіанти

* Числові ідентифікатори (autoincrement).
* UUID (випадкові, наприклад UUID v7).

## Результат рішення

Chosen option: «UUID для всіх первинних і зовнішніх ключів», тому що випадкова генерація унеможливлює вгадування id і витік метрик — обидві вразливості числових ідентифікаторів розв'язані.

### Позитивні наслідки

* Ідентифікатори неможливо вгадати чи аналізувати по порядку.
* Витік метрик (кількість користувачів тощо) ускладнений.
* PK/FK-логіка єдинообразна: всі ключі одного типу.

### Негативні наслідки

* Більший об'єм зберігання ключів і менш щільні індекси.
* Генерація ID дещо повільніша та складніша за керування.
* Для будь-яких майбутніх числових ідентифікаторів довело б додатково заборонити показ їх на стороні користувача — тут ризик знятий самим вибором UUID.

## Плюси й мінуси варіантів

### Числові ідентифікатори (autoincrement)

* Good, because менше навантаження на диск і ОЗП, швидша генерація.
* Bad, because уразливість вгадування id.
* Bad, because витік метрик — легко оцінити кількість зареєстрованих користувачів.

### UUID

* Good, because генерується випадково; вгадування і витік метрик практично неможливі.
* Good, because сучасний стандарт UUID v7 додатково зменшує ймовірність колізій.
* Bad, because більші за розміром і повільніші для індексів у порівнянні з числами.

## Додаткова інформація

Закріплено у критеріях прийняття spec.md: усі PK — `UUID`, усі FK — `UUID`.
